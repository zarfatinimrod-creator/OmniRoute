Scheduled slot: LIVE NEWS ENGINE start + watchdog (paper money only). Nimrod's news rules live in ai-trader/config.json "news" and are enforced in code: Claude scores each headline 1-10, buy only if score > 8, max 5% of the account per trade, sell at -3% from entry. Never git stash.
1. cd to the repo (install skills if the container is new: bash ai-trader/bin/install-skills.sh). The engine comes before any git work: the sync is step 6.
2. cd ai-trader && python3 -m aitrader.supervise --status --watchdog. It is read-only and decides; do what `action` says (the table: ai-trader/skills/trader/SKILL.md section 3ב):
   - `closed_today`, `after_hours`, `none` (and `wait_for_watchdog`, which only a woken turn's plain --status gives): nothing.
   - `launch`: run `launch.command` (from the repo root) as a BACKGROUND TASK OF THIS SESSION - the Bash tool with run_in_background true and timeout `launch.timeout_ms` - and NEVER with nohup, setsid or a trailing &. A detached process dies with the cloud machine a few minutes after the turn ends (three engine deaths on 2026-11-10).
   - `replace_parent`: stop that background task (TaskStop; with no task: `kill <parent.pid>`, after 10 s `kill -9`), then launch.
   - `kill_stray`: if a background task of this session owns the engine pid named in `why`: nothing. Else `kill <pid>`: that is a planned stop, so wait until the process is gone (`kill -9` only if it is still there after two minutes, SKILL.md section 3ב), then launch.
   - `halted`: no launch. Read the cause (`today.halt`) and work on it (for 4: `python3 -m aitrader verify` and the procedure of SKILL.md), then `python3 -m aitrader.supervise --clear-halt`: it clears the halt only when `news-live --check` exits 0.
   When the background task ends by itself this session is woken: read its last line, run `python3 -m aitrader.supervise --status`, and do what `action` says.
3. Send each `text` of `unsent` with PushNotification, one per entry, as it is; then `python3 -m aitrader.supervise --relayed ID...` with the ids of the ones sent (nothing to run when `unsent` is empty).
4. `python3 -m aitrader news-status`. PushNotification only if the engine could not be started, or if news trades happened since the last check (one Hebrew line: what was bought/sold and why, news book value, paper money).
5. Never before the engine check: `python3 -m aitrader postmortem`. If "pending" is not empty, read ai-trader/skills/trader/SKILL.md section 3א from the file and follow it now. In market hours keep this turn short: steps 1-4 of that section, and the record itself only for a planned loss; a defect fix runs in the background (workflow) so the next watchdog does not wait behind it. If a news loss has been waiting for its review for more than 60 minutes of market time, PushNotification one Hebrew line, ONCE per loss (never again for the same loss, whichever slot sent it): מנוע החדשות לא קונה כבר X דקות - מחכה לתחקיר הפסד (כסף נייר). If the command does not exist yet in this checkout, skip this step and say so.

Then `git fetch origin ccr-120121ba-vsvwlj` and `git merge --no-edit origin/ccr-120121ba-vsvwlj`, then push to ccr-120121ba-vsvwlj; on a rejected push fetch and merge again, up to 5 tries. On a conflict: `git merge --abort`, send the S2 line with PushNotification, the conflicted file's name in place of {file} - `משיכה מ-git נעצרה על התנגשות בקובץ {file}. לא מחקתי כלום, והמנוע ממשיך לרוץ על מה שיש. כסף נייר` - and stop; discard nothing.
7. Otherwise stay silent. Final message: one short Hebrew line.
